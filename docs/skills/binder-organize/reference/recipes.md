# 操作別レシピ

いずれも `reference/data-model.md` の書き込みルール（ファイル → 実体テーブル → structures の順、
エスケープ、ゼロ値の日時）に従うこと。

---

## 1. 散らばったメモを 1 つのノートに統合する

index 直下に溜まった断片メモを、テーマごとにまとめる。

1. 統合対象のノート本文を全て読み、話題ごとにグループ分けする
2. グループごとに新しいノートを作る
   - `id` = 新規 UUID v7
   - 本文 = 各メモを見出し（`##`）で束ねて再構成したもの。**元の文言はできるだけ残す**。
     要約して情報を捨てない
   - `parent_id` = 統合先の親（既定は `index`）
   - `seq` = その親の max+1
   - `notes.csv` の `layout_template` / `content_template` = 兄弟ノートからコピー
3. **元のメモは消さない。** 統合先へ `parent_id` を付け替えて子にぶら下げるか、
   そのまま残して削除候補として提案する
4. 元メモを子にした場合は、新ノートの末尾に `{{childNotes -1 "" "seq"}}` を置くと
   元メモへの導線になる

## 2. 長文ノートを章立てして分割する

1. 見出し（`##`）で本文を切り分ける
2. 章ごとに子ノートを作る
   - `parent_id` = 元ノートの id
   - `seq` = 1 から章の順に振る
   - `name` = 見出しのテキスト
3. 元ノートの本文は「導入 + 目次」に置き換える

```
（導入文）

{{childNotes -1 "" "seq"}}
```

4. 元ノートの本文を書き換える前に、必ず全章が子ノートへ移っていることを確認する

## 3. ツリーを再編する（親の付け替え・並べ替え）

`structures.csv` の `parent_id` と `seq` だけを書き換える。実体ファイルには触らない。

- 移動先の親の子を**全部**列挙し、`seq` を `1..n` で振り直す
- 移動元の親の子も同様に `1..n` に詰め直す（穴が空いたままでも動くが、
  アプリで並べ替えると振り直されるので揃えておく）
- `updated_date` / `updated_user` を更新する
- **循環を作らない**（自分の子孫を自分の親にしない）。Validate.ps1 が検出する

## 4. 目次ノートを作る

```
このセクションの内容です。

{{childNotes -1 "" "seq"}}
```

`{{childNotes}}` は `.Name` `.Link` `.Detail` `.Image` `.Publish` を持つ要素を返すので、
`range` で好きな形に整形できる。

```
{{range childNotes -1 "" "seq"}}
### [{{.Name}}]({{.Link}})
{{.Detail}}
{{end}}
```

注意: `childNotes` は**公開済みノート**を返す（プレビューでは未公開も見える）。
未公開のまま目次に出ないのは仕様。

## 5. 本文から Mermaid 図を起こして差し込む

1. 図にする価値がある箇所を選ぶ。**箇条書きで足りるものを無理に図にしない**。
   手順の分岐、状態遷移、コンポーネント間のやり取り、時系列のやり取りが対象
2. 図の id を新規 UUID v7 で採る
3. `diagrams/{id}.md` に **Mermaid ソースだけ**を書く（フェンスなし）

```
flowchart TD
    A[メモを書く] --> B{整理する?}
    B -->|Yes| C[統合ノートへ]
    B -->|No| D[そのまま]
```

4. `diagrams.csv` に行を足す（`style_template` は空でよい）
5. `structures.csv` に `type = diagram` の行を足す。
   `parent_id` = **図を差し込むノートの id**（図はそのノートの子になる）
6. ノート本文の該当箇所に `{{drawDiagram "<diagram_id>"}}` を挿入する
7. `Validate.ps1` で参照が解決することを確認する

使える図の種類は Mermaid に準ずる（`flowchart` / `sequenceDiagram` / `stateDiagram-v2` /
`classDiagram` / `erDiagram` / `gantt` / `mindmap` 等）。

## 6. ノートの説明文（detail）を整える

`structures.csv` の `detail` はツリーと目次に出る。空のままのノートが多いなら、
本文から 1〜2 文の要旨を起こして埋めると一覧性が上がる。

**エスケープを忘れないこと**（改行 `&#10;`、半角空白 `&#32;`、カンマ `&#44;`、`"` `&#34;`）。
detail は複数行になりやすく、ここが最もエスケープ漏れを起こしやすい。

## 7. 削除（ユーザが明示的に指示した場合のみ）

1. 子を持つノートは削除しない。先に子を移動させる
2. `index` は削除しない
3. 削除するもの:
   - 実体ファイル（`notes/{id}.md` 等）
   - 実体テーブルの行
   - `structures.csv` の行
   - 公開済みなら `docs/pages/{alias}.html` 等も残るが、**触らずに残す**。
     アプリの「公開解除」で消すのが正しい
